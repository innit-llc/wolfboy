## What the rule says to do, in full

Read the matched line first, because this rule matches the string
googletagmanager.com and that
string reaches the page in four different shapes, and two of them load the
tag. A \<script> src or
a framework Script component is one of the two, and everything below
applies to it. A \<noscript>
\<iframe> is the other, and no JavaScript-side default can gate it - that
one is fixed by not
rendering the element until a decision is recorded, or by dropping it. A
\<link rel="preconnect"> or
"dns-prefetch" is a network hint rather than a tag: it opens a connection
to Google and sets no
storage, so the change there is to remove the hint alongside whatever load
it was warming, not to
add a consent default. A Content-Security-Policy directive or another
allow-list entry naming the
host is a declaration that the tag is permitted somewhere, not a place
where it loads; find the
actual load and answer for that line instead.
Set the Consent Mode v2 defaults to denied before the first gtag call, then
send an update once the CMP records consent:
gtag('consent', 'default', { ad_storage: 'denied', analytics_storage:
'denied', ad_user_data: 'denied', ad_personalization: 'denied' });
In Next.js, place this inline in the shared layout as \<Script
strategy="beforeInteractive"> at the very top.
If such a call already exists, check the two things it is routinely wrong
about rather than treating its presence as the answer: every category must
be 'denied' (an omitted ad_user_data or ad_personalization leaves that
category on), and it must run on the same load path as this line and before
it — a default in one layout does not cover a page rendered from another.
