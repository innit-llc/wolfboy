## What the rule says to do, in full

This is a candidate for review against ePrivacy Directive 2002/58/EC Art.
5(3) as nationally
transposed, which is this rule's first legal basis. It is not a
determination about this code. The
changes below apply where the review confirms that a third-party tag really
is placed in the
document's initial load path.
Read the matched line first and name its shape, because the change differs
by shape and only one of
the seven shapes this detector matches has a strategy prop to change.
- A pre-hydration strategy prop (Next.js strategy="beforeInteractive",
  Gatsby
  ScriptStrategy.preHydrate): move the tag off it — "afterInteractive" is
  the Next.js default — and
  load the tag from the consent manager's callback instead.
- A script element in a server template or an application shell (ERB, Twig,
  Mustache, Handlebars,
  Blade, HAML, a SvelteKit app.html, an Angular or Vite index.html, a Remix
  or React Router root, an
  Astro script marked is:inline), a Rails javascript_include_tag, or a
  WordPress
  wp_register_script / wp_enqueue_script: there is no
  strategy prop to change here. Take the element or the registration out of
  the shell and let the
  consent manager inject the tag once the visitor has answered, or leave
  the element in place with
  its src moved to data-src, which is how Cookiebot, CookieHub and OneTrust
  hold a tag back until
  consent arrives.
- A tag-manager container snippet, its synchronous injector
  (parentNode.insertBefore,
  document.write) or an inline script written into a React document shell:
  the snippet runs as the
  page parses, so the gate has to sit around the snippet itself — render it
  only after consent, or
  keep it and set the vendor's own pre-consent default ahead of it. Consent
  Mode default-denied is
  that mechanism for Google, and requireConsent is Matomo's; where a vendor
  offers no pre-consent
  mode, the only gate is not loading the snippet until consent is recorded.
  The Google answer does
  not transfer to the other vendors.
- A noscript container iframe or tracking pixel: a JavaScript consent
  manager cannot reach it at
  all, because it fires from static markup with scripting switched off.
  Remove it, or emit it only
  from a server-side branch that already knows consent was recorded.
- A head-population call (useHead, setHeadComponents, a head: or script:
  configuration array, or a
  placement option such as tagPosition, tagPriority or metaInfo) or a
  dangerouslySetInnerHTML
  block: these are placement machinery and may carry no tag of their own.
  Read what is being
  placed before changing anything.
Where the file is documentation, an administration screen that shows an
operator a snippet to paste,
or an integration manifest for a tag this product's own users install,
nothing loads on this
product's own pages and the candidate closes there.
