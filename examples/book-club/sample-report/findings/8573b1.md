## What the rule says to do, in full

The change is to serve the font files from the product's own origin, and
where the reference lives
decides what has to be edited. This rule matches two hosts and they appear
in different places:
fonts.googleapis.com carries the stylesheet, fonts.gstatic.com carries the
font binaries, and
either can appear as a \<link>, as a preconnect or dns-prefetch hint, as an
@import or a
@font-face src inside a CSS or SCSS file, or as a build-tool configuration
value.
Where the reference is a \<link rel="stylesheet"> or an @import, remove it
and add the font through
next/font (Next.js) or fontsource, both of which emit local files at build
time so that no request
leaves the visitor's browser.
Where the reference is a preconnect or dns-prefetch hint, remove it with
the load it was warming; a
hint left behind after the fonts were self-hosted opens a connection to
Google for nothing.
Where the reference is a @font-face src pointing at fonts.gstatic.com,
download the .woff2 files,
commit or bundle them, and point the src at the local path.
Where the reference is a build-time configuration that fetches the font
during the build, the
request is made by the build machine and not by any visitor - record that
and close the candidate
rather than changing anything. A build script that greps the compiled
assets for the font host,
downloads the files and rewrites the references to a local path is that
same shape written in
shell, and the same reading applies: record it and close the candidate.
WHERE THE MATCHED LINE IS AN ASSEMBLED IMAGE URL RATHER THAN A FONT
REFERENCE, none of the
paragraphs above applies and the change is a different one. The image is
fetched by the visitor's
browser from a third party, and where the value spliced into the URL is
derived from the person -
an email digest, a user id - the request key identifies them to that vendor
as well. The change
is to generate the image locally (an identicon rendered from the same value
on this product's own
origin, which is what several products already ship beside the remote
service), or to cache the
remote image server-side and serve it from this origin, or to make the
remote lookup something
the person turns on rather than the shipped default. Where the product
already has a setting that
disables the remote service, say what its shipped default is; a setting
that defaults to on is
the finding, not the remedy.
