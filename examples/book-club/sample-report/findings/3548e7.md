<summary>The review's reasoning, in full</summary>

- What the review said: The code adds a self-service close-account route: a
  member confirms with their own e-mail and password
  (src/account\.ts:10-14), so the person can reach it. The route stops
  short of erasing anything, though. Its only write is src/account\.ts:19,
  which sets closed \= 1 on the member's row. The name, e-mail, password
  hash and avatar URL stay in the members table (src/db\.ts:6-14). I
  searched the tree (excluding \.legal/) for DELETE FROM, purge and
  retention and found no job or code that later deletes the row. The row
  therefore stays indefinitely, while the shipped privacy policy promises
  deletion within 30 days (PRIVACY\.md:20). Nothing in the route tells
  recipients either. The code sends identity to other parties: an e-mail
  hash to Gravatar (src/avatar\.ts:6), the e-mail to the Meta pixel
  (public/app\.js:23) and sign-up events to Google Analytics
  (public/app\.js:22), and the member's name and question to OpenAI
  (src/assistant\.ts:26). The route reaches none of them. Refusal: a wrong
  login returns a fixed 401 message with no Art. 12(4) reasons, but that is
  a credential check and not a refusal to act. The route has no
  response-time or cost barrier. The product is offered in the EU, as the
  person declared. The operator club is the controller and this vendor code
  supplies the mechanism.
