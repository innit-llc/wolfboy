## What the rule says to do, in full

Load the SDK only after a recorded consent decision, or replace the plugin
with a facade:
render a static button and inject the SDK only when the visitor clicks it.
Where the SDK exists only so that an operator can connect a business
account, move the load
behind that action so that it never runs on an ordinary page view.
Where the integration is server-side, use the Graph API from your own
server instead: the
request then carries your server's IP address and no visitor datum is
transmitted.
Wherever the SDK or plugin still loads in a visitor's browser - after
consent, or on a click - tell
visitors, at the latest when it loads, that their data go from this page to
Meta, for what purpose
and on which ground: Fashion ID point 4 puts the duty to inform on the
embedding operator as well
as the consent, and Art. 94(2) maps that duty to GDPR Arts. 13 and 14. The
privacy notice is the
usual place for it, and a consent prompt or a facade button that names Meta
says it at the moment
it matters.
