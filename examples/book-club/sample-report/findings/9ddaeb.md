<summary>The review's reasoning, in full</summary>

- What the review said: The Ask the club route in src/assistant\.ts sends a
  member's first name and typed question to OpenAI's chat API. The call is
  built at src/assistant\.ts:19, and src/assistant\.ts:26 puts \`\${name}:
  \${question}\` in the user message. The name comes from the sign-up form
  through public/app\.js:48 and the question from the ask box. The
  destination is a named hosted vendor, not a model the club runs itself:
  the client at src/assistant\.ts:4 sets no base URL, and INSTALL\.md:25
  says OPENAI_API_KEY is 'your key for the OpenAI API'. The scan profile
  does not say which provider is used, so this rests on the code and
  install text. The credential is one operator-set key from the environment
  (src/assistant\.ts:4), so OpenAI sees the club installation, not each
  member. The body still carries a person-named field, the first name, plus
  free text. The free text is whatever a member types, so it could include
  special-category details; nothing in the code screens it. OpenAI is
  US-established, so a transfer entry would also be needed. The person
  declared the EU, so this rule applies. Whether the club's record of
  processing activities lists OpenAI as a recipient is not in this
  repository. PRIVACY\.md (a starting text) names no AI recipient. I
  searched src/, public/, PRIVACY\.md and INSTALL\.md only. I found no
  self-hosted-model setting and no step that drops the name before sending.
