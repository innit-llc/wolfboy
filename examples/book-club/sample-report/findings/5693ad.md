  password, then runs UPDATE members SET closed \= 1\. That flags the row
  and does not erase it: the name, e-mail, password hash and avatar URL
  stay stored. I searched src/ and public/ for DELETE FROM, erase, portab,
  export, dsar and any scheduled job and found none. The 30-day deletion
  PRIVACY\.md:20 promises therefore has no job behind it in this tree. I
  listed every route in src/: the only GET is /privacy, and the only other
  handlers are signup, ask and the account deletion. So I found no route or
  admin command for access or a copy, a machine-readable export,
  correction, restriction, objection or an automated-decision route. The
  only UPDATE on members is the closed flag (account\.ts:19).
  public/app\.js calls only /api/signup and /api/ask, so the page has no
  delete button either. PRIVACY\.md:24 gives
  privacy\@bookclub\.example\.com. That is a mailbox, and what is done
  after the mail arrives is not shown, so the operator has nothing that
  ships to answer an access or export request with. Assumption: each club
  that installs the software is the controller for its members, and the
  maker supplies the tool. Under either role the missing routes are not in
  the product. The person declared the EU. Other places: the three form
  fields are the sign-up form, db\.ts:9-10 are the stored e-mail and hash
  columns, and bcrypt\.compare and bcrypt\.hash show the account system.
  All are kept as the account store these rights attach to.
