<summary>The review's reasoning, in full</summary>

- What the review said: After a successful sign-up, public/app\.js
  initialises the Meta Pixel with the member's e-mail address (em:
  fields\.email) and then tracks CompleteRegistration. Which half of the
  pixel code this is: the fbq('init') call; the loader is
  public/index\.html:20 and no noscript pixel appears in the page. Guard on
  the call: none; the only condition is the sign-up response succeeding
  (app\.js lines 13-17), which is not a consent decision. There is no
  fbq('consent', 'revoke') or grant anywhere, and the scan's
  consent-vocabulary search found zero files in 14; I also read the whole
  page and script and found no banner. The pixel ID 000000000000000 is a
  placeholder (INSTALL\.md says the installer inserts their own), but the
  code as written sends the address. Sending the e-mail as
  advanced-matching data makes this heavier than a page-view pixel. Served
  from public/ (Dockerfile:7, src/server\.ts:12). The person declared the
  EU; the settled premise says this rule is in scope.

</details>
