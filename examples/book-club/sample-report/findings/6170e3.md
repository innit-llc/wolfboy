## What the rule says to do, in full

Call fbq('consent', 'revoke') on page load before the pixel runs, then
fbq('consent', 'grant') once the CMP records consent.
Alternatively, load the pixel script itself dynamically once the CMP
records consent.
A \<noscript> \<img> pixel cannot be gated in JavaScript at all: render
that element server-side only once consent has been recorded, or drop it.
If a revoke/grant pair already exists, check the two things it is routinely
wrong about rather than treating its presence as the answer: the revoke has
to run on the same load path as this line and before it, and the grant has
to be conditioned on a recorded decision. Neither covers the noscript
pixel.
